# AWS Bastion Host – Interview Explanation

Bastion Host is NOT used to create a public server.
It is used to connect/access private servers from a public network securely.

Bastion Host is a special EC2 instance used to securely access servers located in private subnets from the internet.

### Key Points:

1. Secure Access

   * Private EC2 instances do not have public IP addresses.
   * We cannot directly SSH into private servers.
   * Bastion acts as a gateway/jump server.

2. Location

   * Bastion Host is placed in a Public Subnet.
   * It has a Public IP / Elastic IP.
   * Private servers remain in Private Subnets.

3. Connection Flow

```text
Developer
    |
 Internet
    |
Bastion Host
(Public Subnet)
    |
    |
Private EC2
(Private Subnet)

4. Security

   * Security Group of Bastion:

     * Allow SSH (Port 22) only from trusted IPs.
   * Security Group of Private EC2:

     * Allow SSH only from Bastion Security Group.

### Interview Answer:

> "A Bastion Host is a secure jump server used to access EC2 instances in private subnets. It is deployed in a public subnet with a public IP, and administrators connect to the Bastion first, then access private servers through it. This improves security by preventing direct internet access to private instances."

An Elastic IP (EIP) in AWS is a static public IPv4 address that you can allocate to your AWS account and associate with resources such as an Amazon EC2 instance.

Unlike the default public IP assigned to an EC2 instance, an Elastic IP does not change when you stop and start the instance (provided the EIP remains associated with it).

### Why use an Elastic IP?

You use an Elastic IP when you need a fixed, publicly reachable IP address.

Common use cases include:

* Hosting websites or APIs where clients, DNS records, or integrations expect a consistent IP address.
* Allowlisting (whitelisting) your server's IP in firewalls, partner systems, or databases.
* Quick failover by moving the Elastic IP from one EC2 instance to another if the original instance fails.
* Running VPNs or bastion hosts that users connect to using a fixed IP address.

### Example

Without an Elastic IP:

* You launch an EC2 instance.
* AWS assigns it a temporary public IP, such as `54.12.34.56`.
* If you stop and restart the instance, it might become `18.204.10.25`.
* Anyone connecting to the old IP will fail.

With an Elastic IP:

* Allocate an Elastic IP, for example `3.90.100.50`.
* Associate it with your EC2 instance.
* Even if you stop and restart the instance, the Elastic IP remains the same.
* If the instance fails, you can reassign the Elastic IP to another instance, restoring service more quickly.

### Elastic IP vs Public IP

| Feature                      | Public IP | Elastic IP |
| ---------------------------- | --------- | ---------- |
| Static                       | ❌ No      | ✅ Yes      |
| Persists after stop/start    | ❌ No      | ✅ Yes      |
| Can move to another instance | ❌ No      | ✅ Yes      |
| Manual allocation            | ❌ No      | ✅ Yes      |

### Things to keep in mind

* Elastic IPs are public IPv4 addresses.
* AWS encourages using as few Elastic IPs as necessary because public IPv4 addresses are limited.
* AWS may charge for Elastic IP usage depending on how it is allocated and used, so it's worth reviewing the current pricing before relying on them.

In short, an Elastic IP gives your AWS resource a permanent, movable public IP address, making it useful whenever external systems need a stable address or when you want rapid recovery during instance failures.

Yes, that's correct.

An Elastic IP is not "created" just for you. It is allocated from AWS's pool of public IPv4 addresses.

The process is:

1. AWS owns a large pool of public IPv4 addresses.
2. When you allocate an Elastic IP, AWS reserves one of those addresses and assigns it to your AWS account.
3. You can then associate that Elastic IP with an EC2 instance (or certain other supported resources).
4. If you disassociate it, the IP remains reserved for your account until you release it back to AWS.

For example:

* AWS public IP pool:

    3.10.1.1
  3.10.1.2
  3.10.1.3
  ...
  * You allocate an Elastic IP.
* AWS reserves `3.10.1.2` for your account.
* You attach it to your EC2 instance.
* Even if you stop and start the instance, `3.10.1.2` remains yours until you explicitly release it.

This is different from the default public IP assigned to an EC2 instance. That address also comes from AWS's public IP pool, but it is temporary. If you stop and start the instance, AWS may return that IP to the pool and assign you a different one.

So, a simple way to remember it is:

* Public IP = temporarily assigned from AWS's pool.
* Elastic IP = reserved from AWS's pool specifically for your AWS account until you release it.

### What is Inbound Traffic?

Inbound traffic is the traffic that comes into an EC2 instance.

Example:

* A user opens your website.
* Your laptop connects to the EC2 instance using SSH.
* An application sends an API request to your server.

Interview answer:

> "Inbound traffic is incoming network traffic to an EC2 instance. It is controlled by inbound rules in the Security Group. For example, allowing HTTP (port 80) lets users access a website, and allowing SSH (port 22) lets administrators log in."

---

### What is Outbound Traffic?

Outbound traffic is the traffic that leaves an EC2 instance.

Example:

* The EC2 instance downloads software updates.
* The server calls an external API.
* The server sends data back to a user's browser.

Interview answer:

> "Outbound traffic is network traffic leaving an EC2 instance. It is controlled by outbound rules in the Security Group. For example, an EC2 instance accessing the internet to download updates or call an external API."

---

### Common Interview Question

Q: What are Security Groups?

Answer:

> "A Security Group is a virtual firewall for an EC2 instance. It controls inbound and outbound traffic by allowing specific ports, protocols, and IP addresses. Security Groups are stateful, meaning if inbound traffic is allowed, the response traffic is automatically allowed."

---

### One-line definition to remember

* Inbound: Traffic coming into the EC2 instance.
* Outbound: Traffic going out from the EC2 instance.
* Security Group: A stateful firewall that controls inbound and outbound traffic for an EC2 instance.

These concise definitions are commonly expected in AWS interviews.

You're referring to the types (ranges) of TCP/UDP port numbers. There are 3 categories:

| Port Range        | Type                                    | Used For                                    |
| ----------------- | --------------------------------------- | ------------------------------------------- |
| 0 – 1023      | Well-Known (System) Ports           | Standard services like HTTP, HTTPS, SSH     |
| 1024 – 49151  | Registered Ports                    | Applications registered with IANA           |
| 49152 – 65535 | Dynamic / Private / Ephemeral Ports | Temporary ports used by client applications |

### 1. Well-Known (System) Ports (0–1023)

Reserved for common internet services.

Examples:

* 20/21 – FTP
* 22 – SSH
* 23 – Telnet
* 25 – SMTP
* 53 – DNS
* 80 – HTTP
* 110 – POP3
* 143 – IMAP
* 443 – HTTPS

---

### 2. Registered Ports (1024–49151)

Used by applications and services registered with IANA.

Examples:

* 1433 – Microsoft SQL Server
* 1521 – Oracle Database
* 3306 – MySQL
* 3389 – Remote Desktop (RDP)
* 5432 – PostgreSQL
* 8080 – Alternative HTTP port

---

### 3. Dynamic / Private / Ephemeral Ports (49152–65535)

Used temporarily by client operating systems when connecting to servers.

Example:

* Your browser may use port 55000 to connect to a web server on port 443.

---

### Interview Answer

> "Port numbers are divided into three categories: Well-Known (System) ports from 0–1023 for standard services like HTTP and SSH, Registered ports from 1024–49151 for specific applications like MySQL and PostgreSQL, and Dynamic/Private (Ephemeral) ports from 49152–65535, which are temporary ports assigned by the operating system for client connections."
